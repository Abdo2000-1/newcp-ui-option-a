# Architecture Decision Records

Use this directory for consequential decisions that affect business semantics, public API contracts, data access, authentication, tenant isolation, repository topology, or quality gates.

## Status and ownership

- `Proposed` means a recommendation awaiting the named human approver.
- `Accepted` requires an approver, date, source/decision context, and implementation impact.
- `Superseded` links to the decision that replaced it.
- Do not create an ADR from an illustrative source-package example alone.

## ADR template

```markdown

- Status: Proposed | Accepted | Superseded
```
