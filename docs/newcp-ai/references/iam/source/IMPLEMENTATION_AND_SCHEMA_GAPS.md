# Implementation gaps — developer / DB-owner review, NOT approved schema changes

Inspected V3 fresh ETL's migration sources: `migrations/V006__iam_tables.sql`, `migrations/V005__audit_tables.sql`, and the previously supplied v0.9.2.2 development handoff. The supplied migrations are *design artifacts*. These observations are not live DB schema verification.

1. `iam.users` has tenant-scoped accounts (`tenant_id`, `email`, `state`, `party_kind`, `uuid`, `legacy_*`), `iam.user_roles` and `iam.roles` implement tenant-scoped membership; `iam.capabilities` / `iam.role_capabilities` can support declared capabilities. Confirm the five role codes and exact capability seeds; do not assume they already exist.
2. V006 does **not visibly define a generic Google OAuth immutable provider-subject identity table**. Propose safe identity linking that does not confuse email with immutable Google `sub`, and explain first-time provisioning compatibility with existing migrated `iam.users`. Seek a reviewed schema adjustment if required.
3. V006 has `iam.users.tenant_id`, but **multi-tenant membership lookup / provider identity spanning tenants is not obviously supported** as an independent entity. Current demo needs explicit assignment for tenant 1; do not automatically create membership from `@3ddx.com`. Escalate any missing persistence/approval workflow before promising future multi-tenant support.
4. `iam.user_sessions` defines `issued_at`, `expires_at`, `revoked_at`, `token_hash` but **no `last_activity_at`**. Propose session idle expiration implementation with 30m idle and 8h absolute independent of cookies alone; values config driven, server checked.
5. V005 `audit.event_log.event_code` CHECK includes login/logout, `role_assigned`, `role_removed`, `data_export`, etc., but **no `permission_denied` / `authorization_denied` code**. Propose and review migration/event sink for denied actions; do not insert a new event_code until DB owner authorizes appropriate change.
6. Multi-role union required as business model even though M02 multi-role *test execution* is deferred. Avoid dropping any ability for many `iam.user_roles` per user.
7. Report read and export are distinct policy endpoints/actions. `reports.export` only FINANCE/QC/ADMIN, and attempt is audited. Data shown must be sanitized demo data until per-field production report policy is approved.
8. No F07 DB deployment is verified by this IAM reference. Fresh V3 rebuild with F07-integrated ETL requires DB owner to apply V204, execute and reconcile Stage 30/90, then release actual Bill To editing.
9. Source V0.9.2.2 references describe an *older populated V3 DB* state. Do not treat their past 'F07 columns absent' report as conclusive for the newly rebuilt target. Verify the specific environment being tested.

**Release gate:** obtain an approved schema/seed/API implementation delta with test evidence. Agents must not invent approved table names, Google Group IDs or production data policies.
